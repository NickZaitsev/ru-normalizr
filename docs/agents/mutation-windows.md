# Ограничения mutmut на Windows

Разовый mutation-аудит выполняется только во временном git worktree: `mutmut`
переписывает исходники на месте, а незавершённый прогон оставляет артефакты и
дочерние процессы.

На Windows `mutmut 2.4.5 --use-coverage` запускает отдельный pytest для каждого
мутанта и пересобирает окружение. Даже небольшой модуль с двумя файлами тестов
может не завершиться за пять минут; широкий запуск для `dictionary.py` однажды
разогнал дочерний pytest до десятков гигабайт приватной памяти. Поэтому такие
прогоны нельзя оставлять без контроля: после таймаута нужно остановить дерево
процессов и удалить временный worktree, а новые проверки добавлять по уже
подтверждённым поведенческим случаям.

Проверка 3 августа 2026 года показала дополнительный риск: после запуска из
временного worktree mutmut оставил основной checkout с тем же содержимым файла,
но с изменёнными переводами строк (`LF` → `CRLF`). Это было восстановлено до
исходного состояния. Перед каждым таким запуском нужно проверять `git status` и
в основном checkout, и в worktree; после таймаута — завершать всё дерево
процессов, а не только оболочку.
